# ЛР 3 — Спектр

Игровая презентация материальной системы TurboGameEngine: три витринных
образца, заказ на сбор материалов, настоящие ECS-prefab и шесть тем о решении.
Кнопка **Защита Material Graph** ведёт к докингу, живому предпросмотру и
восстановлению черновика. **К игровому заказу** возвращает к уже начатому заказу.

## Запуск

Из корня репозитория игра открывается одной командой:

```powershell
./tools/lab3/Launch-MaterialLab.ps1
```

Это отдельное окно Play, D3D12, 1600×900, без vsync. По умолчанию игра работает
до закрытия окна/Escape. Для короткого запуска доступен `-Seconds 30`;
другой готовый бинарник задаётся через `-Executable C:/path/to/app.exe`.
Launcher создаёт изолированный snapshot в `.tge/run/<uuid>/`, сохраняет там
логи и оставляет исходную сцену источником live reload. Каталоги не удаляются;
переменная длительности возвращается к исходному значению после выхода.

Для правки свойств открыть проект в редакторе:

1. Открыть актуальный `C:/tge/profile/Release/app.exe`.
2. Projects → Open Existing Project → `Lab3Materials.tgeproj` из этой папки.
3. Для параметров сцены оставить **Explorer** и **Properties** открытыми и выбрать
   **MaterialLabController**. В секции Luau Behavior находятся `rounds`,
   `spinSpeed`, `animate`, `title`. Сохранить сцену после авторских правок.
4. Play in Editor или Play Window. Для читаемого HUD удобно окно от 1100×720.
   Длинная панель прокручивается. Кнопка витрины скрывает задания,
   повторное нажатие возвращает панель лаборатории.

В Editor Play русский HUD рисуется внутри **Viewport**, без отдельного окна
`MaterialLabRoot`. Он следует размеру viewport, обрезается его границами
и отображается поверх gizmo. Ввод UI получает приоритет перед выбором
объектов сцены и управлением камерой. В отдельном Play HUD занимает окно игры.

## Игра и демонстрация

### Материалы на защите за 4 минуты

Для чистого прогона скопируйте `Lab3Materials.tgeproj`, папку `assets` и
`.tge/editor_layout.json` в новый каталог. Откройте копию в редакторе. В Play
нажмите **Защита Material Graph**. Если игра запущена отдельным скриптом, её
окно можно оставить открытым рядом с редактором как подсказку. При запуске
из редактора нажмите **Stop**, чтобы выполнить операции в Edit.

1. **Докинг графа.** Выберите `LayeredMaterialPreview` в **Explorer**.
   В **Properties → Material** нажмите **Open Material Graph**. Перетащите
   разделитель, затем нажмите **Float** и **Dock beside Viewport**. Рядом с
   широким Viewport граф встаёт сбоку, при узкой раскладке снизу. Для показа
   сбоку разверните редактор или сузьте боковые панели. Колесо и средняя кнопка
   меняют масштаб и смещение холста.
2. **Живой предпросмотр.** Если узлы не помещаются на холсте, нажмите **Fit**
   или **Fit Graph**. Перетащите выход **Scalar** (`0.38`) на вход **Alpha**
   узла **Lerp**, заменив связь с **Channel**. В свойствах **Scalar** через
   Ctrl+клик по **Value** и Enter задайте сначала `0.10`, затем `0.85`.
   Выбранная сфера меняется сразу. `LayeredMaterialReference` рядом использует
   тот же материал и продолжает показывать сохранённую версию.
3. **Восстановление.** Нажмите **Undo** в графе один раз. На экране `0.10`,
   а в ветке Redo ещё есть `0.85`. Оставьте граф закреплённым и открытым,
   закройте редактор и снова откройте этот `.tgeproj`. **Save Material**
   отложите до окончания показа. Проверьте восстановление выделения,
   положения холста и предпросмотра. Нажмите **Redo** для `0.85`, затем
   **Undo** для `0.10`. В конце **Discard / Reload** (в компактной панели
   **Discard**) вернёт сохранённую поверхность и очистит историю черновика.

После основной части можно вернуться в Play и создать **Нефрит**, **Аметист**,
**Янтарь**, чтобы показать три режима смешивания на настоящих prefab.

### Заказы и свойства объектов

Заказ просит материал; выбор правильного создаёт sphere из соответствующего
prefab. Последовательность: **Нефрит → Аметист → Янтарь**, затем повтор.
Цель по умолчанию — 6. Неправильный выбор отмечается, прогресс не увеличивается. **Новый заказ**
очищает только собственные образцы. Stop восстанавливает сцену Edit.

Материалы наследуют `materials/base.json`; параметры каждого инстанса можно
менять в панели **Material**. `stage.json → pedestal.json` показывает цепочку
из трёх уровней. Образцы используют один mesh и shader с отдельными данными.
Нефрит непрозрачен (`opaque`), янтарь полупрозрачен (`alpha`), аметист
смешивается с фоном с добавлением цвета (`additive`). У прозрачных материалов
отключена запись глубины, проверка глубины сохранена. Это смешивание цвета,
без эффекта bloom. Образцы разнесены: сцена не заявляет решение сортировки пересечений.

В редакторской панели **Statistics → Materials / frame** видны Draws,
PSO cache hits, PSO created и Errors. Инстансы с одинаковыми shader/blend/depth,
но разным tint должны переиспользовать PSO.

Для пункта 2.6 выбрать **JadePreview** и править SampleMotion: `speed`,
`bobbing`, `height`, `caption`. У контроллера `rounds` задаёт длину следующего
заказа, `spinSpeed`/`animate` управляют созданными образцами, `title` виден в HUD.
Save Scene → следующий Play сохраняет авторские параметры; Save New Prefab
создаёт отдельный шаблон с ними. Play-правки откатываются по Stop.

Подписи **Rotation Speed**, **Bobbing**, **Amplitude**, **Caption** и категории
**Movement/Presentation** взяты из `fields` в `SampleMotion.luau`.
`default` задаёт исходное значение, а `label`, `category`, `description`,
`min`, `max`, `step` описывают его виджет Inspector. Скрипт читает значение
через `self.fields.speed` (ключ поля), независимо от отображаемой подписи.
`caption` выводится в правой части HUD. Изменение подписи активного образца
появляется на следующем тике, не меняя его движение. Список ограничен восемью
живыми объектами; удаление освобождает место для следующего.

## Что показывать на защите

Выбран **вариант Г — материалы как данные**. Три допфичи по 2 балла:
перезагрузка JSON-материалов с обновлением наследников; живой ImGui-редактор
материалов/инстансов; многоуровневое наследование `base → stage → pedestal`.

1. Соберите заказ: правильные ответы создают настоящие ECS-объекты из prefab.
2. Остановите Play, выберите `JadePreview`, поменяйте параметры **Luau Behavior**.
   Покажите ограничения ввода, **R**, **Undo/Redo**, **Save Scene** и следующий Play.
3. Через **Save New Prefab** экспортируйте объект с изменёнными полями в новый
   файл; следующий spawn использует их. Это экспорт одного объекта, без дочерних.
4. В панели **Material** нажмите **Create Instance for This Object...**, затем
   **Create and Assign**: свободное имя уже предложено. Включите галочку
   у цвета или повтора текстуры, измените значение, нажмите **Save Material**.
   Новый материал виден без пересборки C++. Снятие галочки сразу показывает
   значение из базы; файл обновится после сохранения.
5. Измените базовый JSON: зависимые инстансы обновляются. Ошибочная
   перезагрузка оставляет последнее рабочее состояние и выводит диагностику.
   Для первого обращения к нерабочему ресурсу используется fallback.

## Проверка

```powershell
python demos/lab3-materials/check.py --write-only
python demos/lab3-materials/check.py --luau C:/path/to/existing/luau.exe
```

Строгая проверка требует три видимых режима смешивания и те же материалы
у соответствующих prefab, корректные depth-настройки и конечные числовые
значения. Наличие неиспользуемого файла материала не заменяет демонстрацию.

В первом режиме проверяется JSON и готовится bundle без выполнения.
Во втором работает настоящий vendored React с кнопками/событиями, но Engine
заменён явным test double. Это не GPU-тест. Нативный UI, сохранение, hot reload,
замеры и captures проверены отдельными native harness; результаты и ограничения
сохранены в матрице проверки ниже.

Установленный Luau CLI не обязателен: Release-цель `engine_lab3_demo_tests`
исполняет тот же `tests/smoke.luau` в настоящей VM с React и явной подменой
Engine. Отдельные сценарии этой цели используют настоящие ECS и prefab API,
проверяя также Stop с живыми образцами и удаление контроллера во время Play.

[матрица ТЗ и сценарий проверки](../../docs/lab3/verification.md).

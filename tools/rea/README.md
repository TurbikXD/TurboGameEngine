# REA для TurboGameEngine

Локальный REA MCP 6.5.0 из https://github.com/morluto/rea и Ghidra 12.1.4.
Не участвует в CMake и не изменяет глобальную конфигурацию Codex.

## Установка и подключение

Из корня репозитория в PowerShell:

```powershell
./tools/rea/setup.ps1
```

Нужны Node.js 22.x (от 22.19), 24.x (от 24.11) или 26+ и полный JDK 21+.
Поддерживаемые ветки Node задаёт пакет REA; используйте актуальный LTS.
При необходимости передайте `-JavaHome 'C:/path/to/jdk'`.
Установка использует npm lockfile с отключёнными lifecycle scripts и официальный
архив Ghidra с проверкой SHA-256. Зависимости и результаты в `local/` исключены из Git.
Создаётся локальный `.codex/config.toml` с абсолютными путями текущей машины;
после переноса репозитория регистрацию нужно пересоздать вручную.
Чужие MCP-записи сохраняются, отличающаяся существующая запись `rea` не заменяется.

Полностью перезапустите Codex и откройте доверенный проект TurboGameEngine.
Проверьте сервер `rea` через `/mcp`. Проектные настройки действуют только
в этом репозитории; уже открытый чат может потребовать переподключения.
Проектная настройка: https://learn.chatgpt.com/docs/extend/mcp

## Использование

Пример запроса в чате:

> Через REA MCP исследуй `C:/path/program.exe`: как устроена функция [описание].
> Сначала собери факты и ссылки на функции, затем предложи собственную реализацию
> для TurboGameEngine. Результаты сохрани в `tools/rea/local/investigations/`.

Указывайте конкретную программу, интересующую фичу и наблюдаемое поведение.
Исследование и перенос в движок — отдельные шаги; декомпилированный псевдокод
нужно проверить и адаптировать к ECS, ресурсам и жизненному циклу движка.

CLI доступен и без переподключения MCP:

```powershell
node tools/rea/rea.mjs --version
node tools/rea/rea.mjs mcp doctor --json
node tools/rea/rea.mjs doctor --provider ghidra --format json
node tools/rea/rea.mjs inspect 'C:/path/program.exe' --provider ghidra --format json
```

При CLI-проверке JDK должен определяться через JAVA_HOME или PATH;
MCP получает JAVA_HOME из проектной настройки. Холодный импорт Ghidra может
занять длительное время. Вместо прежнего лимита 600 с launcher задаёт
`REA_GHIDRA_STARTUP_TIMEOUT_MS=2147483647` — максимальное поддерживаемое REA 6.5.0
значение (около 24,9 суток). Это общий срок импорта, анализа и готовности Ghidra,
а не отдельный срок каждой фазы. Бесконечность, `0` и отрицательные значения
не поддерживаются: схема REA принимает только целое от 1 до 2147483647 мс;
больший Node timer переполнился бы до 1 мс. Заданное пользователем значение
переменной окружения сохраняется.

Проектный `tool_timeout_sec=2147544` оставляет MCP-вызову этот срок плюс примерно
60 с на завершение/ответ. `startup_timeout_sec=60` относится только к запуску
самого MCP-сервера и не ограничивает последующий импорт Ghidra. Отмена пользователем
по-прежнему действует; отдельные операции провайдера могут иметь свои сроки.
Для применения изменений перезапустите REA MCP или Codex: уже работающий процесс
не перечитывает launcher и конфигурацию. Не запускайте повторную установку ради
изменения таймаута.

Контракт значения проверен в установленном пакете
`node_modules/rea-agents/dist/config/providerStartupTimeout.js` и
`dist/process/ProviderDeadline.js`; настройка MCP описана в
[официальной документации Codex](https://learn.chatgpt.com/docs/extend/mcp#other-configuration-options).

Windows Ghidra в REA экспериментален, поддерживает ограниченный набор операций
статического анализа PE. Наличие сервера не означает поддержку всех платформ
и динамических сценариев. JavaScript/Electron и .NET имеют отдельные средства
статического анализа; дополнительные провайдеры устанавливаются по задаче.
Контракты: https://github.com/morluto/rea/blob/main/docs/windows-ghidra-p0.md

`smoke-fixture.c` — собственная минимальная программа для проверки декомпиляции,
её не требуется запускать. Артефакты проверки размещаются в `local/`.

Проверено 16.10.2026 на Windows x64: MCP initialize и каталог (207 инструментов,
6 prompts), готовность Ghidra/Java/native addon, открытие тестовой EXE,
список функций, декомпиляция `sound_pan` и закрытие через MCP. SHA-256 исходной
EXE не изменился. Отчёты текущей установки: `local/mcp-doctor.json`,
`local/ghidra-doctor.json`, `local/native-mcp-smoke.json`.

# Live-редактирование и FPS

Прогоны 14–15.10.2026. Использована отдельная копия проекта **AI GAME**; исходные
файлы проекта не менялись. Оба режима Play поддерживают автоматическую замену
Luau, зависимостей `require`, React UI и применение изменений startup-сцены.
Порядок работы и поведение `OnReload` описаны в [инструкции проектов](projects.md#live-редактирование).

## Что тормозило

- Обычный запуск выполнялся из `Debug`: `/Od /Ob0 /RTC1`, без оптимизации C++
  движка и интерпретатора Luau. Это особенно заметно на многочисленных вызовах
  ECS из игровой логики. Release использует `/O2 /Ob2`.
- Отрисовывались объекты вне камеры. Добавлены границы meshes и консервативная
  проверка шести плоскостей frustum; в финальном кадре тестовой игры из 552
  render-объектов отправлялись 137, остальные 415 отсекались.
- Медленный кадр порождал очередь fixed updates. До изменения фиксировалось
  6–8 догоняющих шагов за кадр, что дополнительно увеличивало задержку. Для
  обычной игры теперь действуют предел 4 шага и бюджет догоняющей работы 8 мс;
  один уже начатый шаг завершается полностью. Лабораторные режимы сохранены.
  При перегрузке избыток времени отбрасывается: симуляция может замедлиться,
  но очередь не разгоняет задержку ввода и отрисовки. В Release тестовая игра
  успевает выполнять свои 60 шагов/с.
- React pump компилировал служебный Luau chunk каждый тик. Теперь вызывается
  уже загруженная функция под тем же watchdog.
- В проекте есть обходной путь для отсутствующего `Engine.setRotation`: он
  пересоздаёт части персонажей при смене позы. Добавлены `getRotation` и
  `setRotation` (Euler, радианы), поэтому этот обходной путь больше не нужен.
- Сообщения о каждом попадании в resource cache писались на INFO и вызывали
  flush лога. Теперь это TRACE. Контекст открытого скрипта для AI также собирается
  при отправке запроса, без повторного копирования исходника каждый кадр.

Отдельно обнаружено ложное срабатывание 25-мс callback watchdog в неоптимизированной
сборке. Бюджет Debug теперь 100 мс; Release остаётся 25 мс. Явные лимиты через
`setLimits` продолжают действовать. Ошибки Luau и успешные замены кода записываются
в лог, поэтому прекращение работы скрипта видно и в отдельном игровом окне.

## Замер

Одна и та же копия startup-сцены, автоматический выбор фракции elf, без дальнейшего
ввода, D3D12, 1280×720, VSync выключен, Tracy собран, но capture не подключён.
Каждый прогон — 45 с; первые 3 с исключены. N=1 на вариант: это проверка конкретного
сценария, а не гарантия FPS для любых проектов. GPU timestamps отдельно не снимались.

| Вариант | Кадров в выборке | Средний кадр | Средний FPS | CPU update/кадр | CPU render/кадр |
|---|---:|---:|---:|---:|---:|
| Debug до исправлений | 529 | 79,03 мс | 12,7 | 39,70 мс | 37,77 мс |
| Debug после исправлений | 1534 | 27,84 мс | 35,9 | 10,88 мс | 15,06 мс |
| Release после исправлений | 32775 | 1,28 мс | 779,8 | 0,14 мс | 0,36 мс |

В новых прогонах отсутствовали ошибки Luau, игра загрузила 559 сущностей. В Debug
сохраняются задержки первоначальной загрузки ресурсов и стоимость неоптимизированной
логики. Средний самый медленный секундный интервал Release — 1,44 мс, максимальный
отдельный кадр — 19,29 мс. В исходной диагностике длинные кадры обрезались до 250 мс;
теперь статистика записывает фактическое время, а clamp применяется только к симуляции.

Промежуточный Debug-прогон с прежним 25-мс бюджетом был отвергнут: watchdog остановил
игровой callback. Его более высокий FPS не использован в таблице.

Сырые локальные логи: `build/live-validation-20261014-231818/` —
`baseline-console.log`, `final-debug-budget-console.log`, `final-release-console.log`.
Агрегат: `build/live-perf-summary.json`. Для собственного прогона включить
`TGE_FRAME_DIAGNOSTICS=1`: лог содержит CPU-этапы, число шагов, отброшенное время,
draw calls, culling и память Luau. Окружение и глобальные настройки пользователя
не менялись.

Для игры и измерения производительности использовать `C:/tge/profile/Release/app.exe`.
Debug-сборка для C++ отладки остаётся в `C:/tge/clion-vs2022b-rel/Debug/app.exe`.

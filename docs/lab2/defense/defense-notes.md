# Защита ЛР 2: доклад и демонстрация

Дата: 16.10.2026. Источник требований: приложенное ТЗ, SHA-256 `5542fc2a7787fa9b7dfe93b9ffa0a255768361f7710841806afc379614e09e45`.

## Короткий доклад

«Я встроил в TurboGameEngine Luau как отдельную подсистему. C++ отвечает за мир, рендеринг, ввод, ресурсы и физику. Правила игры находятся в скрипте: движение игрока, создание предметов, сбор, начисление очков, таймер и победа. Для изменения правил не нужна пересборка C++.

Одна VM принадлежит игровому миру. Движок вызывает Init, Update, OnEvent, Destroy и OnReload. Экземпляр поведения получает идентификатор сущности, редактируемые поля и своё runtime-состояние. Скрипт обращается к миру через Engine и Input. Проверки поколения идентификатора и отложенное уничтожение защищают границу ECS; работа VM выполняется на потоке владельца.

Префаб - JSON с компонентами, путём скрипта и полями. Поля number, boolean и string доступны в Properties и сохраняются в сцене. Сейчас я покажу, как скрипт создаёт реальные сущности и как изменение поля меняет механику.

При сохранении файла чтение и компиляция уходят в jobs. Готовый результат применяется на потоке VM. Успешная загрузка меняет методы, сохраняет self.state и вызывает OnReload. При ошибке остаётся предыдущая рабочая версия. Это обновление поведения, а не полный снимок VM.

Для UI я подключил настоящий React Luau: hooks и reconciliation принадлежат upstream-пакету. Мой host соединяет retained UI с ImGui и GPU. Реализованы layout, события, bindings, изображения, TextBox, scrolling, TweenService и CanvasGroup. Эта интерактивная презентация использует те же инструменты.

В редакторе есть проекты, сцена и ресурсы, Script Workspace, диагностика, Undo/Redo и два режима Play. Новый общий реестр команд обслуживает ленту Home, Model, Test, View и Script. Stop после Play in Editor возвращает исходную сцену и историю.

Функции сопоставлены с исходниками и тестами. Все локальные изменения перечислены в Git-реестре, включая ещё не закоммиченные. Результаты проверки памяти приведены отдельно с точным сценарием и ограничениями; отсутствие всех возможных утечек я не вывожу из одного графика».

## Живая демонстрация: 180 секунд

| Время | Действие | Что доказываем |
| --- | --- | --- |
| 0:00-0:30 | Открыть `demos/lab2-collectathon/Lab2Collectathon.tgeproj`. В Edit выбрать controller, изменить `pointsPerToken` и Save Scene; показать JSON-префаб с script/fields. | Редактируемое поле сохранено до Play. |
| 0:30-1:05 | Запустить Play. WASD/стрелки, собрать предмет. Проверить начисление по сохранённому полю. | Скриптовая механика, сериализация и применение поля в следующем Play. |
| 1:05-1:55 | В `Collectathon.luau` изменить `self.state.score += self.fields.pointsPerToken` на `self.state.score += self.fields.pointsPerToken * 2`, сохранить и собрать ещё предмет. | Правило обновилось без Stop; счёт/таймер продолжаются. |
| 1:55-2:20 | Внести синтаксическую ошибку, сохранить, показать Errors; исправить и сохранить. | Last-good версия и восстановление после ошибки. |
| 2:20-3:00 | Нажать React-кнопку HUD, показать Output/State. Stop; сравнить сцену до Play. | Реальный UI, диагностика и восстановление редактора. |

Не менять только `default` поля для демонстрации hot reload: сохранённые поля сцены имеют приоритет. Изменения полей во время Play откатываются Stop; сохранение поля показывается в Edit до запуска. Не ставить breakpoint: полноценного VM debugger нет. `Step Tick` продвигает симуляцию на один шаг, а не выполняет строку Luau.

## Интерактивный вариант

Открыть `demos/lab2-defense/Lab2Defense.tgeproj` через Projects, затем Play in Editor или Play Window. Подробный сценарий и команды проверки: [README проекта](../../../demos/lab2-defense/README.md).

Восемь тем можно просмотреть кнопками оглавления. Три ключа выдаются за: ответы об архитектуре; создание и перемещение настоящих префабов; реальный `OnReload` после изменения `ReloadRules.luau` с сохранением контрольного `counter` и `Init=1`. Назад/Далее сами по себе не доказывают hot reload. Прогресс хранится до Stop.

## Ответы на вопросы

**Зачем не писать правила на C++?** Скрипт отделяет поведение и баланс от механизмов движка; автор меняет их без линковки приложения. C++ оставляет контроль над ресурсами и безопасными точками изменения мира.

**Кто владеет сущностью?** Мир ECS. Скрипт хранит проверяемый идентификатор, а не владеющий native pointer. Удаление из callback откладывается; старый handle не должен оживить новую сущность.

**Как загружается модуль?** Через ограниченное чтение, компилятор Luau и граф `require`. Загрузка и вызовы защищены; неизвестные API и невалидные пути дают ошибку.

**Что сохраняет reload?** `self.state` экземпляра поведения. Методы обновляются и можно выполнить миграцию в OnReload. Произвольный стек VM не сохраняется; смена идентичности React-компонента может сбросить hooks.

**Как устроена многопоточность?** Job выполняет чтение/компиляцию. Применение, ECS и VM остаются на owner thread. Shutdown ждёт фоновые работы до уничтожения зависимых объектов.

**Как распространяется язык?** Luau VM/Compiler статически связаны с приложением. Нужны app/DLL, встроенные assets и React-пакеты; Studio, Python, Codex и npm для игры не требуются. Чистая машина отдельно не проверялась.

**React настоящий?** Да, vendored upstream с provenance/хешами. ReactTurbo/ReactRoblox - собственные синхронные host-адаптеры. Это не браузер и не полный Roblox runtime.

**Есть save game?** Есть сохранение сцены, script fields и пред-Play snapshot. Сохранения всего runtime-состояния/VM checkpoint как savegame нет.

**Что означает проверка памяти?** Счётчики процесса выявляют рост и стабильность сценария. ASan/UBSan/LSan проверяют конкретные инструментированные CPU-пути. LSan на выходе не исключает удержание достижимых Lua-таблиц во время сессии; отдельный same-VM stress нужен именно для этого. GPU и драйвер этими проверками не покрыты.

**Почему CLion не показал профиль?** На установленном CLion 2026.1 выбранный Windows/MSVC toolchain возвращает `Perf profiler is not available for selected toolchain`. Скриншот ошибки сохранён. CPU profiler и поиск утечек - разные проверки. Для Valgrind в CLion на Windows нужен WSL toolchain; его установка и глобальная настройка в рамках этой подготовки не выполнялись.

## Перед выступлением

Использовать Release и подготовленный отдельный проект. Заранее открыть нужный скрипт и Properties. Сохранить авторскую сцену до Play; опыты проводить на копии. Закрыть лишние окна, проверить ввод Viewport и читаемость UI на проекторе. Иметь резервные PPTX/PDF. Итог проверки памяти брать из `verification.json` и `memory-report.md`, а не из старого baseline-лога.

# Crash fixes and local diagnostics

An exit code of 3 is a common MSVC abort result, not a unique cause. The editor
path was tested independently of Play. A quoted Luau literal with 32,768
characters reproduced `std::regex_error(error_stack)` in the previous syntax
tokenizer. With no top-level catch this terminated the application. Luau
highlighting now uses a linear scanner. A second rendered reproducer was a valid
quoted string with an escaped newline: comment/string scanning accessed
`line[line.size()]`, triggering a CRT assertion/abort. That boundary is now
checked. UTF-8 boundary reads and stale selections
after document replacement were also repaired. Script loading is bounded to
2 MiB even if the file grows between metadata inspection and reading.

`engine_script_editor_tests` creates an actual ImGui frame and renders/colorizes
long literals/tokens, malformed UTF-8, replacement selections and undo paths.
The UI Demo scripts were additionally colorized through this rendered path.
This reproduces a matching class of editor failure; the original user's crash
cannot be uniquely identified from an old log without a stack.

The scripting runtime also protects host-side behavior setup, Inspector module
and field access, callbacks, field synchronization and reload attachment. A
frozen behavior table or hostile metatable reports a script error rather than
letting a Luau exception escape C++. Regression scenarios are in
`engine_scripting_tests`. Structured React errors retain their raw `message`
without invoking user `__tostring` metamethods.

On Windows, a fatal failure creates a uniquely named directory under
`%LOCALAPPDATA%/TurboGameEngine/crash-reports`. Preserve `crash.dmp`, `engine.log`
and `report.json` together. The report records the build ID, commit, UTC time,
scene, last recorded action, exception code and faulting thread. Use the
matching executable and PDB to resolve the stack. Each process has its own log
snapshot, including Standalone Play and network test windows.

`logs/crash-last.txt` remains a short summary in the working directory for
Play Session diagnostics. See [Lab 5](lab5/README.md) for the report format,
package checks and symbolized stack workflow.

## Send Report

For a configured interactive Windows build, the crash reporter opens a separate
native dialog showing the destination after saving the report. **Send Report**
sends `crash.dmp`, `engine.log` and `report.json` in one ZIP. The dump and log can
contain local paths and process memory. **Open Folder** opens the original
report. The local files stay available after success, cancellation or failure.

Set the developer's HTTPS upload URL in `crash-report-url.txt` beside `app.exe`.
For Lab 5 packages, pass `-CrashReportUrl` to `New-Lab5Package.ps1` or set the
Actions repository variable `TGE_CRASH_REPORT_URL`. The URL is public package
configuration. An environment variable with the same name overrides it for
the current process. Without a configured URL, the engine saves reports locally.

### Hosted inbox for Lab 5

The official Beacon release packages the HTTPS endpoint from
`tools/lab5/crash-report-url.txt`. The receiver in
`tools/crash_reports/vercel` deploys to Vercel. It saves accepted reports as
`reports/<reportId>.zip` in the private Blob store connected to the project
through OIDC. Open the `reports` folder to download a ZIP and read its build ID.
[MGS crash inbox](https://vercel.com/mgs-6c4a/tge-beacon-crash-reports/stores/blob/store_HCfJgu17oWsUL2nv/manage-blobs)

Reports up to 4 MiB go directly to the HTTPS receiver. For ZIPs above 4 MiB
and up to 64 MiB, the receiver issues a five-minute URL scoped to one private
upload. It checks the archive and its SHA-256 before saving it. Staged uploads
expire after one day. Repeating an accepted upload returns the same report ID.

Use `python tools/crash_reports/test_hosted.py <extracted app.exe> <evidence directory>`
to verify the bundled HTTPS address with two synthetic reports. The script
uses generated bytes and does not read the machine's crash folders.

### Local inbox

Start the developer's inbox in a separate terminal to try the flow locally.

```powershell
python tools/crash_reports/receive.py --directory C:/tge/crash-inbox --port 8765
```

Then set `$env:TGE_CRASH_REPORT_URL = 'http://127.0.0.1:8765/crash-reports'` and
start the game from that PowerShell session. In Lab 5, open the project with
`--lab5` and trigger a probe from the game. `--verify` exercises crash collection
without opening the dialog. Use `app.exe --crash-report <report directory>` to
reopen an existing report, or `app.exe --send-crash-report <report directory>`
for explicit submission from a terminal.

Run `python tools/crash_reports/test_send.py <path to app.exe>` to check the
upload against a temporary local inbox using a fresh Lab 5 crash report.

The receiver saves `<reportId>.zip` in its inbox. Its HTTP contract is
`POST /crash-reports` with `Content-Type: application/zip` and a 64 MiB limit.
It acknowledges a saved report with HTTP 201 or an identical retry with HTTP
200, echoing `reportId` in the `X-TGE-Report-Id` response header. To serve actual
players, expose the local receiver through a rate-limited HTTPS reverse proxy
and keep the inbox private. Direct HTTP is supported at `127.0.0.1` for testing.

The UI image path has independent safeguards: immutable bounded encoded
snapshots, dimension validation before decode, bounded cache/pending loads and
GPU-fence lifetime pins. See [visual UI](roblox-ui-visuals.md).
